# CSAP (클라우드 보안인증)

:::info[한 줄 정의]
공공부문에 클라우드를 공급하려면 받는 인증. **시스템 중요도에 따라 상·중·하 3등급제**로, 등급마다 요구 보안 수준과 분리(물리/논리) 요건이 다르다.
:::

:::warning[검증 필요 — 빠르게 변하는 영역]
등급 체계·관할이 개편 중이다. **2026년 들어 공공 클라우드 보안인증을 국가정보원으로 단일화하고 CSAP 체계를 개편한다는 보도**가 있었음 → 사업 추진 전 *현행 제도·관할*을 반드시 최신 확인.
:::

## 1. 등급제 (2023.1 도입 → 2024.2 본격 시행)
획일적이던 인증을 정보보호 수준에 따라 차등화:
| 등급 | 대상(중요도) | 핵심 요건 |
|---|---|---|
| **하** | 민감도 낮은 공개 시스템 | **논리적 분리 허용**(단 시스템·백업·데이터 **물리적 위치 국내** 한정) |
| **중** | 일반 시스템 | 강화된 통제 |
| **상** | 중요 시스템 | **보안 강화**, 가장 엄격 |

- **기존 인증 인정**: 기존 IaaS / SaaS 표준 / DaaS 인증 → **중등급**으로 인정, SaaS 간편 인증 → **하등급**.
- 서비스 유형: IaaS / SaaS(표준·간편) / DaaS.
- 목적: 공공의 민간 클라우드 이용 활성화 + 클라우드 산업 경쟁력.

## 2. 핵심 쟁점
- **물리적 위치 국내 한정**: 하등급조차 데이터·백업의 국내 보관 요구 → 글로벌 CSP는 *국내 리전/전용 구성* 으로 대응.
- 논리적 분리 허용(하등급)이 글로벌 기업 진출의 문을 열었으나, 상·중등급은 더 엄격.

## 3. 타 인증과의 구분
| 인증 | 대상 | 목적 |
|---|---|---|
| **CSAP** | 공공부문 클라우드 공급 | 공공 이용 적격성 |
| **ISMS-P** | 전 산업 | 정보보호·개인정보 관리체계 → [ISMS-P 통제항목 ↔ AWS 매핑](./ismsp-aws-control-mapping.md) |
| **금융보안원 평가** | 금융권 | FSI 클라우드 이용 → [한국 금융 클라우드 규제 — 전자금융감독규정 / FSI 평가 / 망분리](./korea-fsi-regulations.md) |

## 4. 자주 받는 질문
- "공공기관 납품?" → 대상 시스템 등급 확인 → 해당 등급 경로 + **국내 위치** 요건 설계.
- "제도가 바뀐다던데?" → 관할·등급 개편 진행 중 → 최신 고시/공고 확인 후 추진.
